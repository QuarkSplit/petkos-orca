# Library, mesh and plate-material audit — 8 September 2026

Baseline: `302fb11a86`, branch `per-plate-machines`. Source review followed the live GUI call
paths rather than treating earlier work-log claims as acceptance evidence.

## Confirmed defects

| Area | Failure before this repair | Repair |
|---|---|---|
| Library filtering | Recent entries were appended after filtering, reintroducing excluded files and labelling indexed files as outside the library. | One path identity and consistent filters for indexed and recent records. |
| Library input | Document key handling cancelled ordinary typing in the search field. | Keyboard handling respects editable controls. |
| Library discovery | Catalogue refresh depended on a machine-specific external Python script and generated data. | Native folder indexing, persistent roots, refresh and visible directory status. |
| Mesh annotation storage | Repeated face reorder operations could corrupt the packed annotation offsets. | Repack the annotation stream with its face mapping. |
| Mesh merge | Paint replay ignored part transforms; per-part material and non-solid volume semantics were not consistently preserved. | Bake transforms and carry face annotations and material assignments explicitly. |
| Mesh simplify | Geometric replay rejected surfaces moved beyond a tight overlap tolerance. | A separate nearest-surface transfer mode for simplification. |
| Plate appearance | Blank plate colours and auxiliary appearance arrays inherited values from unrelated pool rows. | Each plate owns RGB, colour type, multi-colour strands and finish. |
| Legacy project load | Legacy per-plate colour overrides were resized to zero before filament slots were seeded. | Preserve recorded colour data through migration and slot completion. |
| Plate display | The main viewport, thumbnails and wipe towers used the currently selected plate's palette for other plates. | Resolve the owning plate and cache its palette per rendering pass. |
| Mesh replacement | Repair and reload reused a mesh's old centring shift as if it described the new surface. | Distinguish in-place surface replacement from transferring into a separately transformed volume. |
| Moving between plates | Slot numbers were retained even when the destination assigned different materials to those numbers; copies also shared painted geometry. | Translate used materials at the completed-move boundary, detach instances when remapping is necessary, and remap paint and object/part/layer references together. |
| Overlapping beds | Transfer resolution chose the first intersecting bed, even when an oversized instance still belonged to another bed. | Preserve existing membership while it still intersects; arrange and off-bed re-entry resolve from the new geometry when no valid membership remains. |
| Transfer undo | Detaching a moved instance could create an intermediate undo snapshot containing duplicate, unremapped objects. | Keep automatic detachment inside the originating move's undo transaction. |
| Material selection cancellation | A material or spool-colour update could commit before a dirty-edit or assignment-scope cancellation. | Commit the accepted selection and deferred spool colours together; cancellation restores the previous selection and pool state without changing plate assignments. |
| Retained slices | Preset-selector refreshes invalidated every plate, including unrelated cached slices. | Remove blanket invalidation; changed assignments invalidate affected plates, and retained results are checked against each plate's composed settings. |
| Build resource use | Up to 14 MSBuild workers each enabled unbounded `/MP` compilation; the legacy and Ninja launchers bypassed local limits. | Shared guarded helper for incremental, full and Ninja builds, bounded jobs, Idle priority, memory check and build lock. The full-build script also bounds CMake dependency jobs and `/MP`. |
| Embedded profile identity | Exported JSON profiles could carry the correct name alongside an empty or stale settings ID; the reader ignored the name and lost the profile's identity. | Read the declared name, synchronize its typed ID, retain legacy ID-only profiles, and skip unnamed profiles without blocking geometry import. |
| Embedded profile completeness | GUI loading skipped complete profiles without an installed parent; export could retain a sparse child instead of the full resolved plate profile. | Load complete profiles directly and replace sparse export duplicates with full copies. Incomplete profiles still require their actual parent. |
| Embedded profile selection | Sorting imported profiles shifted the selected index and made an unrelated imported name return the old edited profile. | Restore the selected index by name while retaining unsaved edits and an explicitly unresolved selection. |
| Embedded printer vendor | Machine preset cleanup discarded the existing vendor field, leaving complete imported machines unable to satisfy their recorded vendor identity. | Retain and export the explicit field; installed/direct parent identity remains authoritative, with recorded embedded identity used when no such parent is available. |

## Documentation corrections

- The README called the fork PetkosOrca, linked upstream binaries as if they were its downloads,
  and claimed upstream platform/build instructions were unchanged. It now identifies Podslicer,
  separates upstream reference material, and documents the supported local build path.
- “A bounded planar cut” conflated the active Knife and Separate tools with older bounded-cut
  implementations. The README now names the actual tools.
- “Paint survives everything” in the August work log was too broad. Removing delete gates did
  not verify coordinate transforms, repeated facet permutations or rebuilt surfaces. Exact
  preservation and geometric approximation are now distinguished.
- The architecture guide said the sidebar filament combo writes to the current plate, despite
  the later pool design explicitly removing that write path. The current ownership description
  now agrees with the implementation.
- The guide said the running app must be closed for linking, then later contradicted itself.
  The build helper renames mapped binaries and leaves the running instance undisturbed.
- The old CLI portability note needs qualification: GUI export already embeds fully resolved
  plate presets. CLI still cannot resolve arbitrary names from this machine's installed preset
  directory; archives with unresolved or absent dependencies remain limited by their contents.
- Historical frame-time and byte-identical G-code measurements establish those experiments,
  not a guarantee for every subsequent revision or input.
- Library “ready” and toolpath labels were too strong: having a configured printer does not
  prove readiness, and stored G-code does not prove every plate remains valid. The library now
  describes the recorded contents rather than promising print readiness.

## Remaining boundaries

- A temporarily off-bed object keeps its source-material association in memory until it is
  placed on another bed. Saving and reopening while it remains off-bed does not persist that
  pending association. Ordinary bed-to-bed transfers finish before saving.
- The library is a file catalogue. Add/Remove folder changes what is indexed; it does not move,
  merge or delete projects. Folder availability and unreadable metadata are reported.
- The native CLI cannot resolve arbitrary installed preset names unless their needed settings
  are available in the archive or supplied configuration. This audit does not claim universal
  portability for projects already missing preset dependencies.
- Complete embedded profiles are checked against the current collection's required settings.
  An older profile missing newly required fields still needs its actual parent. Stale typed IDs
  are not rename aliases because several correctly named profiles can share one such ID.
